# UnrealMCP — Command Spec & Roadmap

Our own catalog of MCP commands for this UnrealMCP fork. Goal: grow toward the breadth of
commercial editor-agents (~900 commands / 28 categories) **as a clean-room reimplementation** —
we build our own Python `UserTools` on top of Unreal's public Python API. We use published
*feature lists and usage walkthroughs* only as an **interface spec** (functionality is not
copyrightable); we do **not** copy anyone's source, and we don't decompile closed plugins.

This doc is the source of truth so memory stays lean (memory holds one pointer here, not 900 rows).

## How commands are implemented (no C++ recompile for most)
- Drop `.py` files in `MCP/UserTools/` (capital U — the loader uses `UserTools/`, the README's
  `user_tools` is a typo). Each defines `register_tools(mcp, utils)` and uses `@mcp.tool()`.
- `send_command("execute_python", {"code": ...})` runs code in Unreal's interpreter (`unreal.*`).
- **Action** commands (spawn/set/delete/save/import) → `execute_python`, return success/error.
- **Query** commands that must return data → `print(json.dumps(...))` inside the code and parse
  the response. ⚠ ASSUMPTION: `execute_python` returns captured stdout. **Validate on first run**;
  if it doesn't, either enhance the plugin's python handler to return stdout (small C++ change) or
  add structured C++ handlers (like `get_scene_info`) for those queries.

## Design principles (adopted as our own patterns, from analysis — not code)
1. **Document-based graphs:** build Blueprint/Material/Niagara graphs from one JSON doc
   (`nodes` + `connections` by `ref`, auto-layout, `rollback_on_error`) — not node-by-node.
2. **Read-after-write validation:** commands return enough to verify without re-querying; provide
   `read_*`/`export_*`/`analyze_*` so the agent can confirm before reporting done.
3. **Idempotent layout / append-safe:** re-running layout doesn't disturb existing nodes.
4. **Naming:** `verb_noun` / `verb_target_property` (e.g. `create_blueprint`, `set_actor_property`).

## Workflow — one command at a time
This spec is the roadmap; we promote commands into the live plugin **one at a time**:
1. **Spec** the command here (signature, params, `unreal` API, return shape, validation check).
2. **Implement** just that one into `MCP/UserTools/` (a small file or appended).
3. **Validate** it against a running editor; fix; then tick its box below.
4. Move to the next.

A batch **reference draft** of all 25 M1 commands lives at `docs/drafts/m1_core_reference.py`
(NOT auto-loaded). We copy from it, one command at a time, refining as we validate — so no
untested code ships wholesale.

**Two hard-won infra facts (apply to ALL commands):**
1. **`execute_python` wraps code in triple-SINGLE-quotes (`'''…'''`) before exec** → any `'''` or backslash in the sent code corrupts it silently (status error, empty output). Snippet bodies must avoid `'''`/`\`; pass params as **base64** JSON (`_exec()` does this). `"""` is safe; `'''` is not.
2. **State does NOT persist across `execute_python` calls** (fresh globals each time) — but **`builtins` attributes DO** persist for the editor process. The agent undo ledger is **per-session**: `builtins._UMCP_LEDGERS[session]`, keyed by `PARAMS["_session"]` (injected by `_exec`; one id per writer process). `undo` pops only the caller's session stack → concurrent agents never revert each other's edits (validated 2026-08-14).
3. **Remote Output Log visibility** (no C++ change): the plugin mirrors the editor Output Log to `Saved/Logs/<Project>.log`. `_query()` wraps every snippet in a try/finally that records the log size before, then `unreal.log_flush()` + reads the appended bytes after, surfacing new `Warning`/`Error` lines as `result["_log_warnings"]`. `get_log_tail` reads it on demand. This is how a remote instance "sees" warnings/errors it can't otherwise observe. (Reflection enumeration reads deprecated aliases → `warnings.simplefilter("ignore")` inside `get_actor_properties` keeps that noise out.)
